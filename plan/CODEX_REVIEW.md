# Codex review of the BRD Agentic Vision plan

**November 14, 2026 · Review of Claude Code’s v1.2 plan**

**Decision.** Lane A can start T00 using the bootstrap steps in the Codex copy. Hold downstream full-data dispatch until the real-data run order and stage gates are reconciled. Decide the evaluation unit and evidence coverage rules before committing human labelling time.

The plan has a good basis for parallel work. The contracts give each lane concrete interfaces, the private AVI fixtures pin recorder behaviour to measured values, and detector and agent fakes keep development independent of model access. The risk index and the assumption-based probability have separate purposes. The findings below address where those choices break down at the handoffs.

**Review scope.** All 46 Markdown source files, including the 34 task cards. I confirmed 34 unique locked test files, 183 test functions, balanced fences, and Python syntax for every locked block. I reproduced the original T23 assertion failure and checked the corrected assertion with pandas 2.2.3. Python 3.12.13, FFmpeg and ffprobe 8.1.1 were available on this Mac. The project modules and verifier are still specifications, so the acceptance suite and full-data gates were unrun. Download progress and the organizers’ rules were outside this review.

## Corrections in the Codex copy

- T00 now has an explicit Lane A bootstrap, a consistent classes YAML shape, persistent test directories, and a Python override for Make targets. Feature CLIs run as modules from the current repository root, including locked-test subprocesses. This changes the affected test command lines while preserving what they assert.
- R01 counts and ignores AppleDouble files on the source volume. R02 publishes a combined index from the complete manifest after the early Day 1 run, reusing per-file caches. The canonical index omits timestamps outside the analysis window.
- T23’s null test uses bracket access for the `flags` column. Final QA now references D1–D16 and T27 reports a missing lite database. H01 frame dumps go under the ignored `work/` directory.

These are changes to the plan and test text. The review makes no implementation or gate-completion claim. The findings describe the reviewed version of Claude Code’s plan. The links open the corresponding sections of the public edition.

T00 also describes `classes.yaml` as a list while its locked test expects a `classes:` mapping. Accept T00 when a clean worktree from that commit can list and run its locked tests with the declared Python and FFmpeg. ## Data, identity, and the state database

- **Blocker · R02 can replace the Day 1 index.** The two day-filtered extraction commands write the same `keyframes.parquet`. Day 1 JPEGs may remain on disk while detection reads only Day 2 rows. The copy specifies a final unfiltered resume pass that publishes one atomic index. Reconcile `(file_id, frame_idx)` against the manifest by folder day and camera, and keep out-of-window timestamps out of the published index. The acceptance test should run both day filters and then confirm both days reach detection. [R02 commands](tasks/RUNS.md#r02-keyframe-extraction) · [T06 output and filtering](tasks/T06_extract_keyframes.md#specification) · [T05 keyframe validator](tasks/T05_validators.md#specification)

- **Blocker · The real-data handoffs put labelling ahead of its inputs.** H04 needs tracks for seed sheets, but R04 waits for H04 before it starts tracking. H06 needs baseline samples for its clips, but R05 lists H06 before baseline labelling. Split tracking from identity and baseline labelling from evaluation. Give R05 an L1 validation mode, then exercise the documented run order from a clean work directory through the full submission check. [Run prerequisites](tasks/RUNS.md#full-data-runs-r01r07) · [R04 and R05 commands](tasks/RUNS.md#r04-tracking-linking-identity) · [Labelling CLI inputs](tasks/T15_label_sheets.md#specification) · [Submission validator](tasks/T05_validators.md#specification)

- **High · Cross-camera linking can violate the one-cow constraint.** Pairwise matches can form a transitive chain that groups two simultaneously visible tracks from one camera. Conflicting tag or manual overrides can also assign the same cow twice. Retain uncalibrated tracks as singletons, reject component merges with same-camera frame conflicts, and route contradictory overrides to review or `UNK`. Add regression cases for a three-camera bridge, an entirely uncalibrated track and two incompatible overrides. [T13 linking and grouping](tasks/T13_camera_linking.md#specification) · [T14 override and conflict rules](tasks/T14_identity_assign.md#specification)

- **High · Coverage can credit gaps as observations.** The locked L1 test requires a missing cow-minute to be `observed`, and the spec gives it confidence 1.0 even if all cameras lack footage. The feature card derives coverage from the behaviour label while the contracts derive it from the basis. Preserve the full minute grid with distinct statuses for unavailable footage, an animal unseen in available footage, and unresolved identity. Derive usable coverage and feature support from those statuses. Test a full camera outage, a missed animal and a visible animal labelled `other`. [Basis contract](02_contracts.md#7-basis-and-confidence) · [L1 fill rule](tasks/T10_minutes_bouts.md#specification) · [Locked gap test](tasks/T10_minutes_bouts.md#locked-test) · [Hourly coverage contract](02_contracts.md#813-hourly_featuresparquet-long-format) · [Feature coverage rule](tasks/T22_features.md#specification)

- **High · The shipped database needs frame transforms and final evidence.** T31 drops `crop_box` and `scale`, which the frame browser needs to draw full-resolution boxes on cropped images. R07 builds the database before `make clips`. T23 leaves clip paths empty and T24 only renders paths it receives. Assign clip selection and final risk CSV writing to a task, build SQLite after that step, and persist the frame transform. Verify one overlay with a nonzero crop offset, compare SQLite risk and probability rows to the final outputs, and open the shipped package offline with its approved sample images or explicit tables-only fallback. [T31 frame schema](tasks/T31_state_database.md#specification) · [T33 frame browser](tasks/T33_prediction_dashboard.md#applogicpy) · [T23 clip output](tasks/T23_risk_engine.md#method-implement-exactly-weights-come-from-configsriskyaml) · [T24 evidence rendering](tasks/T24_risk_cards.md#specification) · [R07 command order](tasks/RUNS.md#r07-l2-l3-and-package)

- **High · Approval should determine which evidence enters the ZIP.** T27 includes the entire outputs tree while planning vocabulary treats event media as private. Use an explicit submission allowlist for authorized clips, ID-check frames, traces, and any dashboard sample images. Keep raw video, private fixtures, secrets, and the agent cache outside the archive. Validate only permitted relative paths, and check the extracted ZIP for the files advertised in the README and for forbidden material. ## Evaluation, scoring, and alerts

- **High · Evaluation does not yet support the promised accuracy claims.** H06 produces 10-second labels with `start` and `duration_s`, while T19 joins minute-wide predictions to a `minute` column. A short clip cannot establish the prevailing label for the whole minute. Pick a common scoring unit and a canonical label export, resolve double labels before scoring, count unmatched predictions and report the random and targeted strata separately. Resample paired temporal blocks for the ablation interval. H05 also excludes only hours 08 and 10 while H04 seeds at dusk. Derive the identity holdout from the actual seed intervals, and reserve a separate final detection set if R03b selects a model. H03’s count score can be perfect when every detection is wrong. Rename it as a count metric or collect held-out boxes and match by overlap to report detection recall. Require an end-to-end run from the actual label sheet exports, with the denominator and exclusions in the report. [Label contract](02_contracts.md#816-human-label-files-labels), [H03–H06](tasks/HUMAN.md#h03-detection-check-100-frames), [T19 metrics](tasks/T19_evaluation.md#specification), [Evaluation protocol](04_testing.md#8-behaviour-and-identity-evaluation-protocol-m40-m50)

- **High · Close the agent's batch hand-off and evidence checks.** R06 reads `agent_cases.parquet`, yet T21 only returns a table with no case camera, and the plan leaves merging committed results into L1 implicit. Specify the producer, camera and time adapter, and rules-only versus reviewed output merge, including trace IDs through minutes and bouts. Lane B can own this integration through T20/T21, with T10 consuming the final sample table. Require positive, typed, case-local evidence for a commit, including a nonempty citation list. T18's default weak feeding estimate has confidence 0.5 while the gate uses `< 0.5`. Cover that boundary in a test. Require an offline end-to-end fixture run, and gate any external image call on the recorded H09 approval with a tested no-network path for pending or denied approval. Enforce budget using measured usage including retries. [T18 rules](tasks/T18_cues_rules.md#specification), [T20 loop and CLI](tasks/T20_agent_core.md#clientpy), [T21 case schema](tasks/T21_gate.md#specification), [R06](tasks/RUNS.md#r05-l1-outputs-and-evaluation)

- **High · Coverage can create a false behaviour signal.** T22 and T23 feed raw visible counts to day and herd comparisons. A cow visible for half as long can appear to feed half as much. The coverage flag only checks day 2 and leaves rankings and scenario outputs untouched. Define paired exposure and per-feature eligibility for both days, distinguish an unmeasured cue from an observed zero, and make zero denominators and missing data explicit. For example, the baseline has no head-down producer, yet drinking requires that cue. Require tests for unequal exposure at the same behaviour rate, zero denominators and unmeasured drinking. Mark unavailable estimates in the dashboard. [T18 cues](tasks/T18_cues_rules.md#specification), [T22 features](tasks/T22_features.md#goal), [T23 method](tasks/T23_risk_engine.md#method-implement-exactly-weights-come-from-configsriskyaml)

- **High · P(BRD) needs a defined scenario and visible provenance.** Keep the adjustable dashboard and define the target event and time horizon. H10 asks for incidence to fill a prevalence parameter and suggests converting mean behaviour differences directly to log-odds per relative score. A study can motivate an assumption while leaving that conversion unsupported. Name the current values as illustrative where unsupported, show the effective prior and effects with each scenario, and label the band as sensitivity to resampled hours and the prior under fixed effects. A penalized fit alone cannot establish calibration. Require the UI to show provenance and update its assumption labels when a slider moves, and describe synthetic injections as tests of model behaviour. [H10](tasks/HUMAN.md#h10-literature-priors-for-the-pbrd-model), [T32 model](tasks/T32_brd_probability.md#goal), [T33 UI](tasks/T33_prediction_dashboard.md#applogicpy)

- **High · Live alert decisions are underspecified for the demo clips.** The default `down_flat` confirmation takes 600 seconds, which exceeds D10's five-minute clip unless warm state includes prior observations. The locked test overrides it to 10 seconds. The warm risk adjustment has no formula, and the tier rules leave visible head signs ambiguous between `urgent` and `check_today`. Specify preconditions and output for unavailable checks, behaviour adjustment and tier precedence. Rehearse an unseen short clip offline, and test that insufficient history, unavailable checks and zero detections stay distinguishable from a completed check that found no qualifying sign. [D10](01_project_definition.md#2-definition-of-done-project-completion--100), [T26 default, tiers and tests](tasks/T26_live_alerts.md#specification)
